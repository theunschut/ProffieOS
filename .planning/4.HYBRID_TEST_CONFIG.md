# Phase 4, Task 4.3: Hybrid Mode Test Configuration

**Objective:** Document test scenarios validating that compiled `StylePtr<...>` and `StyleFromSD(...)` styles coexist without conflicts.

**Status:** Phase 4 Integration & Format Support

---

## Overview

Hybrid mode allows mixing compiled styles (in ROM) with SD-card-loaded styles (parsed at runtime). This configuration demonstrates test scenarios ensuring both formats work seamlessly together.

**Test Approach:**
- Document preset configurations mixing both style sources
- Define verification matrix with success criteria
- Provide example scenarios for different use cases
- Include edge cases and error conditions

---

## Preset Configuration Examples

### Example 1: Pure Compiled Style (Baseline)

**ROM Preset (in config file):**
```cpp
Preset preset_compiled = {
  font: "font1",
  track: "track1",
  style_allocator0: StylePtr<Layers<Blue,Black>>(),
};
```

**Test Goal:** Establish baseline behavior with standard compiled style

**Verification Steps:**
1. Load preset from ROM config
2. Blade displays blue color
3. No parsing errors or warnings
4. No SD card access needed

**Expected Behavior:** ✓ Style loads immediately, colors correct

## Success Criteria

### Functional Success
- ✓ ROM preset activates without issues
- ✓ Disk SD preset activates without issues
- ✓ Switching from ROM to disk smooth (no glitches, color change consistent)
- ✓ Switching from compiled to SD blade colors correct
- ✓ Both styles render the same visual appearance when equivalent
- ✓ Missing files handled gracefully (safe fallback, no crash)

### Quality Criteria
- ✓ No memory leaks or crashes during style deactivation/activation
- ✓ Serial output shows appropriate logging (no spam, clear errors)
- ✓ Frame rate stable during style switching
- ✓ Power control correct (blade powers off when style effects complete)

### Performance Criteria
- ✓ Preset switching: <100ms (imperceptible)
- ✓ SD file parsing: <500ms (acceptable startup delay)
- ✓ Frame rate: within 5% of compiled equivalent

## Manual Verification Steps

### Step 1: Environment Setup
```
1. Copy presets.ini to SD card root
2. Place style files in /config/styles/
3. Connect saber to power
4. Open serial monitor (115200 baud)
```

### Step 2: ROM Preset Verification
```
1. Boot system with ROM config
2. Observe preset selection UI
3. Select compiled style preset
4. Check serial output: [INFO] Preset loaded: Preset #X
5. Blade should display color correctly
6. No parsing errors in serial output
```

### Step 3: SD Preset Verification
```
1. Boot system with presets.ini available
2. Select SD-loaded preset from UI
3. Check serial output: [INFO] Loading style from SD: test_simple.style
4. Blade should render style matching compiled equivalent
5. Timing and colors correct
```

### Step 4: Hybrid Switching
```
1. Select ROM compiled preset
2. Wait 3 seconds, observe blade
3. Select SD-loaded preset
4. Observe smooth transition (no flicker/artifact)
5. Blade color updates to SD style
6. Switch back to compiled
7. Verify return smooth
```

### Step 5: Error Condition
```
1. Activate preset with missing file
2. Observe blade goes to safe black
3. Serial output shows: [WARN] Style file not found: nonexistent.style
4. Saber remains responsive
5. Can switch to different preset
```

### Step 6: Memory Monitoring (if available)
```
1. Use memory monitor (if available via config)
2. Activate and deactivate multiple presets 5-10 times
3. Observe no consistent memory growth
4. Verify allocator returning memory properly
```

## Known Limitations

### ROM Presets (Phase 4 Limitation)
- ROM presets don't yet support `StyleFromSD()` in Preset struct
- Workaround: Use presets.ini for SD-loaded styles
- Planned for future enhancement (Phase 5 or later)

### Path Resolution (Phase 4 Implementation)
- Will attempt paths in order: `/config/styles/` → `/styles/` → root
- Relative paths work from SD root
- Font-relative paths not supported (future enhancement)

### Validation (User Responsibility)
- No automatic syntax validation in .ini file
- Malformed style expressions fall back gracefully
- Users should test custom styles

## Troubleshooting Guide

### Blade Stays Black (SD Load Error)
**Possible Causes:**
1. Style file not found (check paths)
2. File syntax invalid (check format in task 4.5)
3. Parser doesn't recognize token (check logs)

**Verification:**
- Check serial output for error messages
- Verify file exists and is readable
- Try simpler test_simple.style first

### Smooth Transition Glitches
**Possible Causes:**
1. Style instantiation slow (parsing overhead)
2. Allocator not cleaning up previous style
3. Blade state not reset between presets

**Verification:**
- Check frame rate stable in serial output
- Increase delay between switches (test if timing helps)
- Monitor allocator memory usage

### Performance Regression
**Possible Causes:**
1. Virtual dispatch overhead on complex styles
2. Parser re-parsing on each frame (shouldn't happen)
3. Large embedded image/data in style

**Verification:**
- Profile frame rate with "top" command
- Compare simple vs complex styles
- Check if compiled equivalent also slow
