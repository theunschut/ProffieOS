## ProffieOS Preset System Architecture

**Preset Loading Flow:**
1. User places `presets.ini` on SD card root
2. ProffieOS boots, reads `presets.ini` via `CurrentPreset::Read()`
3. Each preset entry contains: `name`, `font`, `track`, `preset.style` (one per blade)
4. At preset selection, `style_allocator` factory is invoked: `factory->make()` → `BladeStyle*`
5. `BladeStyle::run(blade)` called per-frame to update blade LEDs

**Current Status (Phase 3):**
- `StyleFromSD()` API exists and works (lines 4354-4356 in sd_style.h)
- Returns `StyleFactory*` compatible with `StyleAllocator` typedef
- Not yet integrated into presets.ini loading flow

**Key Integration Points:**
- `common/current_preset.h`: Parses variable names from presets.ini (line 127: `f->readVariable(variable)`)
- Currently handles: `name`, `font`, `track`, `end`, `new_preset`
- Does NOT yet handle `preset.style` references with function calls like `StyleFromSD(...)`
- `mk_builtin_str(preset_num, blade_num)` creates style string (line 102): used for ROM presets

**Hybrid Mode Mechanics:**
- ROM presets: `preset->style_allocatorN` (N=blade number) via `Preset` struct
- Disk presets (presets.ini): `current_style_[N-1]` loaded from file
- Both use same `StyleFactory*` interface → compatible at runtime
- No conflict if both compiled and SD styles exist in same config

| presets.ini parser breaks on `StyleFromSD(...)` syntax | Medium | Critical | Task 4.1: Parser extension with test cases |

| Compiled and SD styles conflict at same blade | Low | Medium | Task 4.3: Isolation test with both formats |
| User forgets quotes or syntax errors in .ini | High | Low | Documentation (Task 4.5) |
