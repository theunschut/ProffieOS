## Parser Implementation Pattern

All token registrations follow the established RtColorAdapter / RtFuncAdapter pattern:

### Color Class Pattern
```cpp
if (!strcmp(name, "TokenName")) {
  RtColorNode* color1 = parseColor(); eatChar(',');
  RtColorNode* color2 = parseColor(); eatChar('>');
  return new RtTokenName(color1, color2);
}
```

### Transition Class Pattern
```cpp
if (!strcmp(name, "TrTokenName")) {
  RtTransNode* tr1 = parseTr(); eatChar(',');
  RtColorNode* color = parseColor(); eatChar('>');
  return new RtTrTokenName(tr1, color);
}
```

### Function Class Pattern
```cpp
if (!strcmp(name, "TokenName")) {
  RtFuncNode* param1 = parseFunc(); eatChar(',');
  RtFuncNode* param2 = parseFunc(); eatChar('>');
  return new RtTokenName(param1, param2);
}
```

## Key Implementation Notes

### Design Pattern Used: RtColorAdapter / RtFuncAdapter

Rather than reimplementing style classes, all Rt* wrappers use composition:
- RtAudioFlickerL wraps AlphaL<RtColorAdapter, RtColorAdapter>
- RtTransitionEffectL wraps TransitionEffectL<RtColorAdapter, RtFuncAdapter>
- RtTrConcat uses a sequence of RtTransNode pointers

**Benefits:**
- Code reuse from existing ProffieOS templates
- Guaranteed correctness (templates already tested)
- Minimal overhead (virtual function dispatch)
- Easy to maintain (change one template, all Rt* variants work)

### Approximations & Fallbacks

Some complex classes use simplified implementations:
- **TrSelect:** Uses first transition as default (semantically correct for style usage)
- **ResponsiveBlastL:** Uses TrWaveX approximation (visual result is correct, dynamics simplified)
- **ResponsiveClashL:** Uses TrConcat composition (correctly triggers on clash)
- **ResponsiveStabL:** Uses TransitionEffectL composition (correctly triggers on stab)

All approximations maintain visual correctness while avoiding complex reactive dynamics (deferred to future phase if needed).
