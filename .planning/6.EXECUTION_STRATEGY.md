## Implementation Strategy

### Pattern: Reuse Existing ProffieOS Templates

**Key Insight:** Don't reimplment. Wrap existing template classes using RtColorAdapter/RtFuncAdapter pattern.

**Examples:**

```cpp
// RtAlphaL wraps AlphaL<RtColorAdapter, RtFuncAdapter> ✓ (Phase 4)
class RtAlphaL : public RtColorNode, public AlphaL<RtColorAdapter, RtFuncAdapter> {
  using Base = AlphaL<RtColorAdapter, RtFuncAdapter>;
public:
  RtAlphaL(RtColorNode* color, RtFuncNode* alpha) {
    color_.node_ = color; alpha_.node_ = alpha;
  }
  ~RtAlphaL() override { delete color_.node_; delete alpha_.node_; }
  void run(BladeBase* blade) override { Base::run(blade); }
  RGBA_um getColor(int led) override { return Base::getColor(led); }
};

// RtHumpFlickerL follows same pattern ✓ (Phase 6.1)
class RtHumpFlickerL : public RtColorNode, public HumpFlickerL<RtColorAdapter, RtColorAdapter> {
  using Base = HumpFlickerL<RtColorAdapter, RtColorAdapter>;
  // Same structure...
};
```

**Benefits:**
- Correctness: Uses proven ProffieOS templates
- Simplicity: No reimplementation
- Maintainability: Single source of truth
- Performance: Existing optimizations preserved
