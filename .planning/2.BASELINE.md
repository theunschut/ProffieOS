## Consolidation Analysis

### RtHardStripes & RtStripes

**Current RtStripes (simplified):**
```cpp
class RtStripes {
  // Member variables
  RtVec<RtColorNode*> colors_;
  RtFuncNode* width_;
  RtFuncNode* speed_;

  virtual bool run(BladeBase* blade) { ... }
  virtual RGBA_um getColor(int led) {
    // Smooth interpolation
    return MixColors(...);
  }
};
```

**Current RtHardStripes (simplified):**
```cpp
class RtHardStripes {
  // Same members as RtStripes
  RtVec<RtColorNode*> colors_;
  RtFuncNode* width_;
  RtFuncNode* speed_;

  virtual bool run(BladeBase* blade) { ... }
  virtual RGBA_um getColor(int led) {
    // Hard-edged output (no smoothing)
    return colors_[index]->getColor(led);
  }
};
```

**Consolidation Strategy:**
- Single `RtStripes` class with `bool hard_edge` member
- Parser creates RtStripes with hard_edge=false for "Stripes"
- Parser creates RtStripes with hard_edge=true for "HardStripes"
- getColor() branches: `if (hard_edge) { ... } else { ... }`
- **Net: Save ~20 lines (remove one class), add ~5 lines (parameter logic) = -15 net**

### InOutSparkTipX Simplification

**Current Issue:**
- Uses `decltype` workarounds for template instantiation
- Multiple MixColors calls that could be consolidated
- Custom getColor() is ~45 lines

**Simplification Strategy:**
- Ensure all intermediate colors normalized to RGBA_um early
- Single MixColors call with result

- **Net: Save ~5-8 lines**
